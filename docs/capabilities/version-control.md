# 6. 버전 관리

> 원문: <https://dora.dev/capabilities/version-control/>

## 정의

**버전 관리(Version control)** 시스템(Git, Subversion, Mercurial 등)은 파일을 논리적으로 조직하고, 팀·조직 전반의 생성·접근·갱신·삭제를 조정하는 수단입니다. 자동화·지속적 통합과 밀접하며, 연구는 포괄적 버전 관리 사용이 **지속적 딜리버리를 예측**한다고 일관되게 보여줍니다.

AI 시대에 이 역량은 더 강력합니다. **강한 버전 관리 관행은 AI 도입이 개인 효과성과 팀 성과에 미치는 긍정 효과를 증폭**시킵니다.

## 왜 중요한가: 재현성과 추적성

- **재현성(Reproducibility)**: 어떤 환경이든 완전 자동으로 프로비저닝하고, 같은 구성에서 재현한 새 환경이 동일함을 알 수 있어야 한다.
- **추적성(Traceability)**: 어떤 환경이든 모든 의존성의 버전을 빠르고 정확히 파악하고, 두 버전 간 차이를 비교할 수 있어야 한다.

이로부터 **재해 복구, 감사 가능성, 더 높은 품질, 용량 관리, 결함 대응**이라는 이점이 나옵니다.

## AI 관점: 속도를 위한 안전망

AI 도입으로 코드 생성의 양과 속도가 극적으로 늘어납니다. 이는 처리량을 높이지만 **딜리버리 불안정성 증가**와 함께 나타납니다. 강한 버전 관리는 AI 생성 코드를 자신 있게 실험할 수 있게 하는 **필수 안전망**입니다.

AI는 강력한 **비결정성**을 개발자 워크플로에 들여오므로, "준비되면 커밋"하는 옛 모델은 불충분합니다. 외부 루프(깨끗하고 리뷰 가능한 변경)의 규율을 **내부 루프로 가져와**, 깨끗한 상태마다 **작고 잦은 커밋**을 만들어야 합니다.

또한 버전 관리는 이제 **AI 산출물을 저장하는 곳**입니다.
- **AI 프롬프트**를 버전 관리해 지식을 공유하고 감사 추적을 만든다.
- **에이전트 설정 파일**(예: `GEMINI.md`, `CLAUDE.md`)을 버전 관리해 팀 규범과 가드레일을 세운다.

## 구현 방법: 무엇을 버전 관리하는가

팀은 다음 자산을 공유 저장소에 체크인해야 합니다.

- 모든 애플리케이션 코드와 의존성(라이브러리, 정적 콘텐츠)
- 데이터베이스 스키마·참조 데이터 생성 스크립트
- 환경 생성 도구·산출물(Terraform 파일 등)
- 컨테이너 생성·구성 파일(Dockerfile 등)
- 모든 자동화 테스트·수동 테스트 스크립트
- 패키징·배포·DB 마이그레이션·환경 프로비저닝 스크립트
- 지원 산출물(요구사항 문서, 배포 절차, 릴리스 노트)
- **AI 산출물(프롬프트, 에이전트 설정 파일)**
- 컨테이너 오케스트레이션(Kubernetes, OpenShift 등)
- 모든 클라우드 구성 파일(CloudFormation, Pulumi 등)
- 기타 인프라 지원 스크립트·구성

## 흔한 함정

- **제한적 적용**: 애플리케이션 코드에만 버전 관리를 적용. 베스트 프랙티스는 모든 테스트·프로덕션 환경 재현 능력을 요구한다.
- **내부 루프 방치**: AI로 코드를 빠르게 생성하면서 "완벽해질 때까지" 커밋을 미루면 버전 이력의 안전을 잃는다.
- **머지 충돌**: 잦거나 복잡한 충돌은 long-lived 브랜치 같은 프로세스 문제의 신호다. AI가 만드는 높은 코드량이 이를 악화시킨다.

## 개선 방법

- 모든 커밋이 버전 관리 정보만으로 어떤 환경에든 배포 가능한 패키지 자동 생성을 트리거하게 한다.
- 버전 관리의 스크립트·구성만으로 프로덕션 유사 테스트 환경을 필요 시 생성하게 한다.
- 테스트·프로덕션 인프라를 스크립팅해 용량 추가·재해 복구를 완전 자동화한다.

## 측정 방법

- **커밋 빈도**: 높은 빈도는 높은 개인 효과성과 연관, 특히 AI 사용 시
- **롤백 의존도**: 잦은 롤백은 팀 성과에 대한 AI의 긍정 효과를 증폭
- 애플리케이션 코드 / 시스템 구성 / 애플리케이션 구성 / 빌드·구성 자동화 스크립트의 버전 관리 비율과 복구 용이성
