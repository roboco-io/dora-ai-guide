# 3. 건강한 데이터 생태계

> 원문: <https://dora.dev/capabilities/healthy-data-ecosystems/>

## 정의

**건강한 데이터 생태계(Healthy data ecosystems)** 는 **고품질·쉽게 접근 가능·통합된** 내부 데이터로 정의되며, AI 도입이 조직 성과에 미치는 긍정 효과를 유의하게 증폭시키는 기반 역량입니다.

DORA 연구는 **AI 도입의 긍정 효과가 건강한 데이터 생태계에 달려 있음을 높은 확신으로** 확인했습니다. 데이터 건강도가 높을 때 AI의 조직 성과 긍정 효과가 크게 증폭됩니다.

## AI 관점: 왜 지금 데이터 건강인가

"쓰레기가 들어가면 쓰레기가 나온다(garbage in, garbage out)"는 그 어느 때보다 유효합니다. 건강한 생태계에서는 파인튜닝·RAG 같은 정교한 작업이 가능해지고, AI는 범용 어시스턴트에서 조직의 아키텍처를 이해하는 **전문가**로 이동합니다. 반대로 데이터가 파편화·저품질이면 AI는 **틀린 답을 더 빠르게** 생성합니다.

## 구현 방법

1. **데이터를 부산물이 아니라 제품으로 대한다.** 애플리케이션의 '배기(by-product)'가 아니라 소비자가 있는 제품으로 보고, 핵심 데이터 도메인(예: 고객 계정 데이터)에 **소유자·스튜어드**를 지정해 정확성·메타데이터·접근 정책을 책임진다.
2. **"단일 진실 원천(single source of truth)" 우선.** 사일로가 주요 차단 요인이다. 핵심 데이터 소스를 찾아 통합·연합해 통합 뷰를 만든다.
3. **데이터 품질 프레임워크 도입.** 코드에 자동화 테스트가 있듯, 데이터에도 자동 검증·모니터링을 넣어 정확성·완전성·적시성을 확보한다.
4. **거버넌스와 함께 접근을 민주화.** 팀과 도구가 데이터를 쉽게 발견·접근하도록 하되, 안전하고 문서화된 **"paved road"** 를 만든다.
5. **로컬 문서화.** 문서·메타데이터를 데이터 옆에 두고 코드 산출물처럼 취급한다(예: README.md의 "data" 섹션).

## 흔한 함정

- **"도구가 곧 사일로" 함정**: 특정 도구가 데이터 아키텍처를 결정하게 두지 말 것.
- **데이터를 부산물로 취급**: 소유권·전략이 없으면 사람과 AI 모두를 혼란스럽게 하는 **데이터 늪(data swamps)** 이 된다.
- **바다를 끓이기**: 모든 데이터를 한꺼번에 고치려 하지 말고, 고가치 서비스 하나에 묶인 파일럿으로 시작한다.

## 측정 방법

**설문 문항**
- 필요한 내부 데이터 소스에 얼마나 쉽게 접근·분석할 수 있는가?
- 데이터가 사일로화되어 중요한 내부 데이터를 쓰지 못하는 일이 얼마나 자주 있는가?
- 주로 의존하는 데이터의 전반적 품질은 어떤가?
- 필요한 데이터 포인트를 검색 1시간 내에 확실히 얻을 수 있는가?

**시스템 지표**
- 데이터 적시성: 필요한 데이터셋 접근 권한 획득까지 걸린 시간
- 데이터 인시던트: 데이터 품질에 기인한 버그·프로덕션 인시던트 수
- 데이터 신선도: 핵심 데이터셋의 "last updated" 타임스탬프 분석
