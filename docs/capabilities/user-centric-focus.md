# 5. 사용자 중심

> 원문: <https://dora.dev/capabilities/user-centric-focus/>

## 정의

**사용자 중심(User-centric focus)** 은 팀이 사용자 니즈를 이해하고, 사용자 경험을 우선하며, 피드백을 활용해 작업 우선순위를 지속적으로 재조정하는 정도로 정의됩니다. 디자인 철학을 넘어 **측정 가능한 역량**이며 조직 성과를 견인합니다.

> **사용자에게 집중하는 팀은 조직 성과가 40% 더 높다.**

## AI 관점: 증폭의 방향타

사용자 중심은 AI 시대에 더욱 중요해졌습니다. **AI는 증폭기**이며, 사용자 중심이라는 나침반이 없으면 AI의 코드 생성 가속은 팀을 **더 빠르게 잘못된 방향으로** 밀어붙일 뿐입니다.

- **성과 증폭**: 사용자 중심이 강한 팀이 AI를 도입하면 효과성·팀 성과가 커진다. 사용자 중심성이 **북극성** 역할을 한다.
- **"기능 공장(feature factory)" 함정**: 사용자 중심 없이 AI를 도입하면 팀 성과가 **오히려 해로울 수 있다.** 산출물(출시 기능 수)에 최적화된 팀은 AI로 저가치 소프트웨어를 더 빠르게 양산한다.

## 구현 방법

- **사용자 피드백 루프 통합.** 인앱 설문·직접 관찰 세션 등 **저지연 채널**로 피드백을 받고, 즉시 팀이 우선순위 재조정에 사용한다. AI 지원 팀에게 이 피드백은 **프롬프트 정제**와 AI 출력이 사용자 니즈에 맞는지 검증하는 데 필수다.
- **사용자 지표를 가시화.** 대시보드가 velocity·배포 빈도만 보여주면 사용자는 잊힌다. CSAT·작업 완료율·H.E.A.R.T. 지표를 기술 지표와 나란히 눈에 띄게 배치한다.
- **엔지니어를 사용자 리서치에 참여시킨다.** PM·UX 리서처는 엔지니어와 사용자 사이의 **연결을 촉진**해야지 거리를 강제해선 안 된다. 개발자가 사용자 테스트 세션을 직접 관찰하면 지속적인 공감이 생긴다.
- **스펙 주도 개발(Spec-driven Development, SDD) 활용.** 코드를 쓰기 전에 사용자 니즈·제약을 상세 문서(스펙)로 정제하고, 이를 AI 에이전트의 **진실 원천**으로 삼아 생성 코드가 실제 요구사항에 묶이게 한다.

## 흔한 함정

- **기능 공장 마인드셋**: 결과(사용자 가치)가 아니라 산출물(velocity, 출시 기능)을 측정한다. AI가 이를 악화시킬 수 있다.
- **이력서 주도 개발(resume-driven)**: 특정 AI 모델 등 새 기술을 문제 해결이 아니라 그 자체로 도입하는 '솔루셔니즘'.
- **조직 사일로**: 개발자와 최종 사용자를 체계적으로 단절시키는 '게이트키퍼' 모델은 AI 출력을 검증할 깊은 맥락을 앗아간다.

## 측정 방법

**제품 성과**: 채택률, 유지율, 고객 만족도.

**피드백 통합**: 사용자 피드백이 기능 우선순위·스펙 변경으로 이어진 빈도.

**팀 정렬**: 다음과 같은 진술에 팀이 동의하는 정도
- "사용자에게 가치를 만드는 것이 우리의 초점이다"
- "사용자가 성취하려는 것을 명확히 이해하고 있다"
