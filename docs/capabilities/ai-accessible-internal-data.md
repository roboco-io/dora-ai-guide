# 1. AI가 접근 가능한 내부 데이터

> 원문: <https://dora.dev/capabilities/ai-accessible-internal-data/>

## 정의

**AI가 접근 가능한 내부 데이터(AI-accessible internal data)** 는 AI 시스템을 조직의 독점 정보 — 코드베이스, 문서, 운영 지표 — 에 안전하게 연결해 **맥락을 인식한 응답**을 가능하게 하는 역량입니다. 흔히 **컨텍스트 엔지니어링(context engineering)** 이라 불리는 이 작업은 범용 AI 모델을 조직의 아키텍처·표준·비즈니스 로직을 이해하는 **전문가**로 바꿉니다.

개발자에게 필요한 "브리핑 패킷" 전체를 제공하는 것에 비유할 수 있습니다. 여기에는 사내 코드베이스·아키텍처 다이어그램, 위키·문서·스타일 가이드, 운영 지표·로그가 포함됩니다.

DORA 연구는 AI 도구가 내부 데이터에 직접 접근할 때 AI 도입의 긍정 효과가 **개인 효과성과 코드 품질에 대해 통계적으로 유의하게 증폭**됨을 확인했습니다.

## AI 관점: 프롬프트 엔지니어링 → 컨텍스트 엔지니어링

단순 프롬프트는 비서에게 명령 하나를 주는 것과 같습니다. 컨텍스트 엔지니어링은 최신 API 문서·사내 정책·규격에 맞는 코드 조각을 **자동으로 수집**해 지능적 워크플로를 운영하는 **시스템**입니다.

- **가속**: 온보딩·디버깅에서 '구전 지식(tribal knowledge)'을 즉시 답변으로 전환, 사내 표준에 대한 자동 검증
- **리스크**: 작은 배치를 무시하면 딜리버리 불안정, 폐기된 패턴을 학습하면 기술 부채 증폭, 접근 통제 미비 시 민감 정보 노출

## 구현 방법(3단계)

### 1단계: 기초·수동
- 프롬프트 엔지니어링을 **수동 컨텍스트 엔지니어링**으로 발전시킨다.
- 재사용 가능한 **컨텍스트 템플릿/브리핑 패킷** 라이브러리를 버전 관리와 함께 만든다.
- 무엇보다 **내부 데이터의 품질**이 선행되어야 한다. 없는 데이터에 연결할 수 없고, 틀린 데이터에 연결해선 안 된다. **고품질 문서가 AI 도입의 주요 동인**이므로, 가장 중요한 문서부터 개선한다.

### 2단계: 자동화 파일럿
- 자체 구축(RAG 라이브러리 등) 또는 상용 도구 도입을 결정하고, **고가치 유스케이스 하나**에 적용한다.
- 원문 문서를 통째로 컨텍스트에 넣는 것은 종종 **환각을 유발**한다. 대신 가장 관련성 높은 맥락만 제공한다.
  - **RAG(검색 증강 생성)**: 최신·관련 정보만 정밀하게 검색·제공
  - **MCP(Model Context Protocol) 서버**: 필요한 맥락만 지능적으로 선택·구조화해 공급

### 3단계: 스폰서십 확보·확장·운영화
- 파일럿 성과로 리더십 투자를 확보한다.
- 기반 데이터 문제 해결과 **안전한 내부 API** 구축을 통해 확장한다.

## 흔한 함정

| 함정 | 완화책 |
|---|---|
| 품질 낮은 "엉망인" 내부 데이터 | 고가치 데이터 소스 하나로 파일럿, AI로 정제를 도움 |
| 폐기된 프로젝트까지 인덱싱해 나쁜 습관 학습 | **골드 스탠더드 저장소**로 '커리큘럼'을 구성 |
| 거대 컨텍스트 창에 과부하(컨텍스트 부패) | 양이 아니라 관련성. RAG/MCP로 필요한 청크만 검색("컨텍스트 하베스팅") |
| 슈퍼유저/공용 서비스 계정으로 연결 | **최소 권한** 원칙, 사용자 자격증명으로 검색 동작 |

## 측정 방법

**설문 문항(5점 척도 등)**
- 맥락 인식 AI 응답이 정보 탐색 노력을 줄였다
- 코드베이스를 이해하는 능력을 높였다
- 검증에 드는 노력이 줄었다
- 정보 탐색 시간이 감소했다

**시스템 지표**
- 검색 이벤트 빈도(RAG 쿼리 성공 횟수)
- 데이터 소스 접근률
- AI 검색 지연(time-to-context)
- 쿼리 성공/오류율
- 컨텍스트 풍부 프롬프트 비율
- 신규 개발자 온보딩 시간(N번째 변경을 프로덕션에 배포하기까지)
