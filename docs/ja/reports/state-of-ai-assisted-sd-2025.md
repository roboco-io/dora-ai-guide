# State of AI-assisted Software Development (2025)

> 発表: 2025年9月 · 原文: <https://dora.dev/research/2025/dora-report/>

## 一文要約

**AIの主な役割は増幅器（amplifier）** である。つまりAIは、組織がすでに持つ強みだけでなく弱みも拡大する。AI投資の最大のリターンは、ツールではなく**その下にある組織システム**への戦略的集中から生まれる。

## 背景: 「トリロジー」の中心

2025年のDORAレポートは名称を「Accelerate State of DevOps」から**State of AI-assisted Software Development**に変え、DORAを独立した名前としました。本レポートは2024 Impactレポートを継ぐ中心軸であり、2025 AI Capabilities Modelの母体となります。

## 主要な数値

| 指標 | 値 |
|---|---|
| 仕事でAIを使う技術専門家 | **90%** |
| AIが生産性を高めたと答えた割合 | **80%以上** |
| AI生成コードを「ほとんど／まったく」信頼しない | **約30%** |
| AI導入↑ → デリバリー処理量 | **増加** |
| AI導入↑ → デリバリー安定性 | **低下（不安定の増加）** |

## 中心命題

### 1. AIは増幅器である
- 社内プラットフォームの品質が高く、API・ワークフロー・テストが堅牢なら、AIは強力な協働者になる。
- ツールが分断され、データがサイロ化し、インフラが脆弱なら、AIは**技術的負債をより速く生む**手助けをする。

### 2. 処理量と安定性のトレードオフ
AI導入が高いほど、**処理量と不安定さがともに増加**します。AIが生成速度を高めてバッチが大きくなり、レビュー・検証の負担が増えるためです。これは[AI Capabilities Model](/ja/reports/ai-capabilities-model)の7つのケイパビリティで対応します。

### 3. Jカーブ（生産性の落ち込み）
新しい技術を導入すると、学習・プロセス調整により**一時的に生産性が下がる区間**が生じます。この落ち込みを耐え、戦略的に実行してこそ上昇曲線に乗ります。

### 4. 4つから5つへ進化したデリバリー指標
DORAは伝統的な「4 keys」を**5つの指標**に拡張しました。

1. 変更リードタイム（Change lead time）
2. デプロイ頻度（Deployment frequency）
3. 失敗デプロイの復旧時間（Failed deployment recovery time）
4. 変更障害率（Change failure percentage）
5. デプロイ再作業率（Deployment rework rate）— *2025年追加*

## このレポートが残したもの

- **測定は結果中心に。** 活動量ではなく成果を見る。
- **文化とシステムが技術より先行する。** 心理的安全性、学習文化、ユーザー中心。
- **「AI導入率」ではなく「AIの効果」を目標に。** 導入は必要条件であり、効果はシステムが生む。
