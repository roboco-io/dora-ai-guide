# State of AI-assisted Software Development (2025)

> 発表: 2025年9月 · 原文: <https://dora.dev/research/2025/dora-report/>

## 一文要約

**AIの主な役割は増幅器（amplifier）** である。つまりAIは、組織がすでに持つ強みだけでなく弱みも拡大する。AI投資の最大のリターンは、ツールではなく**その下にある組織システム**への戦略的集中から生まれる。

## 背景: 「トリロジー」の中心

2025年のDORAレポートは、それまでの「Accelerate State of DevOps」ではなく**State of AI-assisted Software Development**というタイトルで発表されました。本レポートは2025年3月に公開されたImpact of Gen AIレポートを継ぐトリロジーの中心軸であり、2025 AI Capabilities Modelの母体となります。

## 研究方法と限界

本レポートは、世界の技術専門家5,000名近く（nearly 5,000）のサーベイ回答と100時間を超える定性データ（インタビューなど）に基づいています（根拠: [Google Cloudの発表ブログ](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report)）。レポート本文によれば、サーベイは2025年6月13日から7月21日まで実施されました。サーベイは回答者の自己報告に基づき、一時点のデータを分析しているため、以下の数値はAI導入と成果の間の**関連**を示すにとどまり、因果関係を立証するものではありません。サンプルの地域・職種構成と統計モデルの詳細はこの要約では確認できていないため、原文PDFを参照してください。

このページでは、データで確認された内容を「観察」、結果を説明しようとする仮説を「説明の可能性」、組織への提案を「推奨」と区別して記します。

## 主要な数値（観察）

| 指標 | 値 |
|---|---|
| 仕事でAIを使う技術専門家 | **90%** |
| AIが生産性を高めたと答えた割合 | **80%以上** |
| AI出力を「少し信頼している」または「まったく信頼していない」 | **約30%** |
| AI導入↑ → デリバリー処理量 | **増加** |
| AI導入↑ → デリバリー安定性 | **低下（不安定の増加）** |

## 中心命題

### 1. AIは増幅器である
組織の既存のケイパビリティ水準によってAI導入と成果の関係が変わる、というのが本レポートの中心的な解釈です。

- 社内プラットフォームの品質が高く、API・ワークフロー・テストが堅牢なら、AIは強力な協働者になる。
- ツールが分断され、データがサイロ化し、インフラが脆弱なら、AIは**技術的負債をより速く生む**手助けをする。

### 2. 処理量と安定性のトレードオフ
AI導入の水準が高いほど、**処理量と不安定さがともに高く現れます**（因果ではなく関連）。2024年の研究はその説明として、AIがコード生成速度を高めることでバッチが大きくなり、レビュー・検証の負担が増す点を説明の可能性として示しました（[Impact of Gen AIの要約](/ja/reports/impact-of-gen-ai-2024)）。DORAはこの緊張への対応として、[AI Capabilities Model](/ja/reports/ai-capabilities-model)の7つのケイパビリティを推奨します。

### 3. Jカーブ（生産性の落ち込み）
新しい技術を導入すると、学習・プロセス調整により**一時的に生産性が下がる区間**が生じます。DORAは、この落ち込みを失敗と判断せず、計画に織り込んで戦略的に実行するよう推奨します。Jカーブは本レポートが示す解釈の枠組みであり、落ち込みの幅と期間は組織によって異なりえます。

### 4. 4つから5つへ進化したデリバリー指標
DORAは伝統的な「4 keys」を**5つの指標**に拡張しました。

DORAは前の3つの指標を**処理量（throughput）**、つまり変更がどれだけ速く流れるかを見る指標に、後の2つの指標を**不安定さ（instability）**、つまりデプロイがどれだけ頻繁に問題を起こすかを見る指標に分類します（根拠: [DORA指標ガイド](https://dora.dev/guides/dora-metrics/)、[DORA指標の沿革](https://dora.dev/insights/dora-metrics-history/)）。

1. 変更リードタイム（Change lead time）— 処理量。変更がバージョン管理にコミットされてから本番環境にデプロイされるまでの時間。
2. デプロイ頻度（Deployment frequency）— 処理量。一定期間のデプロイ回数、またはデプロイの間隔。
3. 失敗デプロイの復旧時間（Failed deployment recovery time）— 処理量。即時の介入が必要な失敗デプロイから復旧するまでの時間。
4. 変更障害率（Change fail rate）— 不安定さ。全デプロイのうち、デプロイ直後にロールバックやホットフィックスなど即時の介入が必要になったデプロイの割合。
5. デプロイ再作業率（Deployment rework rate）— 不安定さ。全デプロイのうち、本番障害のために計画外で行われたデプロイの割合。*2024年レポートで導入*

## このレポートが残したもの

- **測定は結果中心に。** 活動量ではなく成果を見る。
- **文化とシステムが技術より先行する。** 心理的安全性、学習文化、ユーザー中心。
- **「AI導入率」ではなく「AIの効果」を目標に。** 導入は必要条件であり、効果はシステムが生む。
