# AI出力の正確性を超えた懸念

> 発表: 2025年6月 · 著者: Kevin M. Storer · 原文: <https://dora.dev/insights/concerns-beyond-accuracy-of-ai-output/>

## 核心命題

ハルシネーション・不正確さへの懸念が議論を支配してきましたが、8名の深層インタビュー（約90分）の結果、開発者は**正確性以外にも11のカテゴリの懸念**を持っており、そのうち**5つは半数以上が言及**しました。

## 5つの主要な懸念

| 懸念 | 内容 |
|---|---|
| **データプライバシー** | 社内データが基盤モデルの学習に使われ流出しうるという不信。エンタープライズライセンス契約にもかかわらず「規約文言は変えられる」という懐疑 |
| **スキル低下(deskilling)** | AI依存が進み個人のコーディング力が退化し、なければ業務ができないのではという不安。「人として切れ味が鈍る」という認知能力低下への懸念まで |
| **雇用の代替** | 生産性向上が結局開発職をなくすかもしれないという懸念。ただし**自分の職のリスクではない**と見る — 主に扇情的な見出しのため |
| **悪用** | マルウェア生成、精巧なフィッシング、**モデルポイズニング・プロンプトインジェクション**などの新たな攻撃ベクトル |
| **開発文化への影響** | 革新的解決策の**帰属(attribution)** の伝統が弱まるなど開発文化の変化 |

## 懸念に対応する5つの戦略

1. **許容利用ポリシー(AUP)を明確に伝え続ける。** 多くのエンタープライズツールは顧客データを学習に使わないと明示し、一部は著作権紛争の免責まで提供します。それでも開発者が個人の責任を恐れるのは**AUPの明確さの不足**を示します。明確で周知されたAUPは信頼とデータセキュリティ責任の理解を助けます。

2. **AI関連スキル開発の機会・スラックタイム・リソースを提供。** プロンプトエンジニアリングのような新スキルが必要になる一方、**既存スキル維持の不安**が存在します。どの能力を手放し維持するか不確実な過渡期に、新スキルを強調し時間を与えると懸念が和らぎます。AIの普及を**学習機会としてフレーミング**すれば業務価値の認識も保たれます。

3. **雇用不安に向き合い開発業務の未来を共に描く。** AI支援ツールが現在の開発業務の核心（コード生成・文書作成）を代替するため恐怖が大きい。しかし委譲すれば**より高い抽象度**で働く機会が生まれます。開発者を未来設計の過程に招くことが重要です。

4. **速く高品質なフィードバックに投資し、AI生成コードのサンドボックス化などの新たな防御層を検討。** プロンプトインジェクションなど新しい脆弱性に対応し、デプロイ前にテストするサンドボックス化が必要かもしれません。DORAは速く高品質なフィードバックがデリバリー成果・組織成果・ウェルビーイングに寄与することを一貫して示しています。

5. **功績は功績ある場所へ。** AIと共に解に至るにも**実際の労働**が必要です。この労働を明示的に認めることが信頼と価値認識に重要です。

## 結論

正確性の改善が続いても、開発者が持つ**他の懸念に直接向き合う**ことが重要です。AI支援ツールが開発者と社会に最大限有益となるよう設計されるためには、どの限界が最も重要か議論を広げる必要があります。
