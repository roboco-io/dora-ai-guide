# トークンマキシング時代のバランス

> 発表: 2026年6月 · 著者: Evan Conaway · 原文: <https://dora.dev/insights/finding-balance-in-the-era-of-tokenmaxxing/>

## 核心命題

一部の企業が**AIトークン消費量を社内リーダーボードで追跡・報酬化**する「**トークンマキシング(tokenmaxxing)**」を導入しました。DORAはこれを**活動量指標(vanity metric)の繰り返し**と見なし、「maxxing」の修辞を超えて**バランスとチーム単位のケイパビリティ**に集中するよう勧めます。

## 背景

2026年初頭に登場したトークンマキシングは、開発者のマインドセットと組織文化をAI利用へ押しやろうとする試みです。DORAの *State of AI-assisted Software Development* は**約30%の開発者がAI出力を「少しだけ/まったく」信頼しない**と明らかにしました。一部のリーダーはリーダーボードで「トークンを燃やさなければ進化していない」というメッセージを伝えます。

歴史的に行数・コミット頻度といった活動量指標は生産性最適化の近道を約束しましたが、ソフトウェア開発の測定は単一指標に還元できません。

## 潜在的な利点（限定的）

- **初期導入の促進**: AIに消極的な開発者が低い負担で探索できるゲーミフィケーション。
- **パワーユーザーの発掘**: トークンを多く使う開発者の中から高効率なワークフロー・プロンプト戦略を持つ人を見つけ、**「AIチャンピオン」**として知識を拡散。

## 非常に現実的な欠点

- **生産性の演劇(productive theater)**: トークン数は純粋な**投入(input)**指標で操作が容易。「社内平均を超えようと」無意味なプロジェクトで自律エージェントを走らせる事例が報告されています。**グッドハートの法則**: 指標が目標になると、もはや良い測定ではなくなる。
- **財政・技術コスト**: 予算の大きいチームも**10倍のコストで処理量はわずか**しか増えません。レビューなしの低品質AIコードを受け入れ**技術的負債**を増やします。
- **文化的逆効果**: リーダーボードが**雇用不安**を煽り、知識の囲い込み（自分の最良のプロンプトを隠す）を促し、静かで精密なエンジニアリングを埋もれさせます。

## 代替案

- **結果指標への転換**: Salesforceの**AWU(Agentic Work Units)** のように生の入力を完了した成果物へ変換。Shopifyはリーダーボードを**「利用ダッシュボード」**に変え、暴走エージェントを捉える**サーキットブレーカー**を導入しました。
- **チーム・アプリ・ユースケース単位の測定**: 全社集計は無意味で個人スコアは有害です。チーム/アプリ/ユースケース単位で測定しましょう。
- **7つのケイパビリティで条件を整える**: [明確なAIポリシー](/ja/capabilities/clear-and-communicated-ai-stance)、[ユーザー中心](/ja/capabilities/user-centric-focus)、[社内プラットフォームへの投資](/ja/capabilities/platform-engineering)で、AI支援開発者が成果を出せる組織条件を整えましょう。
- **既存の成果指標を活用**: Starburstはトークン最大化を無視し、**標準的なDORA指標・開発者速度・インシデント解決時間**でAIの成功を測定します。さらに**受理された変更あたりのコスト、コード再作業率**といった効率・リスク指標を加えれば正確な像が得られます。

## 結論

トークンのゲーミフィケーションは一時的な活動急増をもたらしますが、**技術的負債とバーンアウト**を代償にします。持続可能な成果は**チームの協働、総合的な結果測定、構築方法のバランス**から生まれます。**「maxxing」を離れる**時です。
