# 7つのケイパビリティ概要 (AI Capabilities Model)

DORA *AI Capabilities Model* は、**AI導入のポジティブな効果を有意に増幅させる7つのケイパビリティ**を示します。このセクションでは各ケイパビリティを定義・実行・測定の観点で要約します。

## 全体マップ

```
              [5] ユーザー中心  ← 方向（北極星）
                     │
   [1] AIがアクセスできる社内データ ─┐
   [3] 健全なデータエコシステム ─────┤ 入力・文脈
   [2] 明確で共有されたAIスタンス ───┘
                     │
              [4] プラットフォームエンジニアリング  ← デリバリー・安全
                     │
        [6] バージョン管理 · [7] 小さなバッチ  ← 安全網・規律
```

## 7つのケイパビリティ

| # | ケイパビリティ | 一文定義 | AIの視点 |
|---|---|---|---|
| 1 | [AIがアクセスできる社内データ](/ja/capabilities/ai-accessible-internal-data) | 社内のコード・文書・指標をAIに安全に接続 | 汎用AIを社内の専門家に変える |
| 2 | [明確で共有されたAIスタンス](/ja/capabilities/clear-and-communicated-ai-stance) | 何を・なぜ・どう使うかを明確に発信 | 心理的安全性 → 実験を促進 |
| 3 | [健全なデータエコシステム](/ja/capabilities/healthy-data-ecosystems) | 高品質・アクセス可能・統合された社内データ | 増幅の前提条件 |
| 4 | [プラットフォームエンジニアリング](/ja/capabilities/platform-engineering) | セルフサービス・ゴールデンパスの社内プラットフォーム | 下流のボトルネックを除く |
| 5 | [ユーザー中心](/ja/capabilities/user-centric-focus) | ユーザーニーズ・体験・フィードバックを優先 | 増幅の舵 |
| 6 | [バージョン管理](/ja/capabilities/version-control) | 再現性・追跡性の確保 | AIの安全網 |
| 7 | [小さなバッチで作業する](/ja/capabilities/working-in-small-batches) | 小さく頻繁な変更 | 不安定さへの対応 |

## DORAが確認した増幅関係

- **プラットフォーム品質が高い** → AI導入の組織パフォーマンス効果は強いポジティブ。**低い** → 効果は僅少。
- **データの健全性が高い** → AIの組織パフォーマンス効果を有意に増幅。
- **明確なAIスタンス** → 個人の効果性・組織パフォーマンスを増幅し、摩擦を減らす。
- **バージョン管理** → 個人の効果性・チームパフォーマンスへのAI効果を増幅。
- **小さなバッチ** → 製品パフォーマンスへのAI効果を増幅。

## 新規ケイパビリティ vs. 強化されたケイパビリティ

| 区分 | ケイパビリティ |
|---|---|
| AI時代に**新たに浮上** | 1, 2, 3, 4 |
| AIによって**より重要に** | 5, 6, 7 |

## 実行原則

1. **一度に一つ。**「海を沸かすな」— 高価値のユースケース1つでパイロット。
2. **測定なくして改善なし。** 各ケイパビリティの設問とシステム指標を併せて見る。
3. **文化と技術を一緒に。** データを「製品」、プラットフォームを「社内製品」として扱う。
4. **結果中心。** 導入率ではなく成果で成功を定義する。
