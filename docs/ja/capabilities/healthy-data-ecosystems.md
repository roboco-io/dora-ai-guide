# 3. 健全なデータエコシステム

> 原文: <https://dora.dev/capabilities/healthy-data-ecosystems/>

## 定義

**健全なデータエコシステム(Healthy data ecosystems)** は、**高品質・容易にアクセス可能・統合された**社内データで定義され、AI導入が組織パフォーマンスに与えるポジティブな効果を有意に増幅させる基盤ケイパビリティです。

DORA研究は、**AI導入のポジティブな効果が健全なデータエコシステムに依存することを高い確信をもって**確認しました。データの健全性が高いとき、AIの組織パフォーマンスへのポジティブ効果が大きく増幅されます。

## AIの視点: なぜ今データの健全性か

「ゴミを入れればゴミが出る(garbage in, garbage out)」はかつてなく有効です。健全なエコシステムではファインチューニング・RAGのような高度な作業が可能になり、AIは汎用アシスタントから組織のアーキテクチャを理解する**専門家**へ移行します。逆にデータが分断・低品質なら、AIは**誤った答えをより速く**生成します。

## 実装方法

1. **データを副産物ではなく製品として扱う。** アプリケーションの「排気」ではなく消費者がいる製品と見なし、重要データドメイン（例: 顧客アカウントデータ）に**オーナー・スチュワード**を割り当て、正確性・メタデータ・アクセスポリシーに責任を持たせる。
2. **「単一の真実の源(single source of truth)」を優先。** サイロが主要な阻害要因。重要データソースを特定し統合・連携して統合ビューを作る。
3. **データ品質フレームワークを導入。** コードに自動テストがあるように、データにも自動検証・監視を入れ、正確性・完全性・適時性を確保する。
4. **ガバナンスとともにアクセスを民主化。** チームとツールがデータを容易に発見・アクセスできるようにしつつ、安全で文書化された**「paved road」**を作る。
5. **ローカルに文書化。** 文書・メタデータをデータの隣に置き、コード成果物のように扱う（例: README.mdの「data」セクション）。

## よくある落とし穴

- **「ツールがサイロ」の罠**: 特定のツールにデータアーキテクチャを決めさせない。
- **データを副産物として扱う**: 所有権・戦略がなければ、人とAIの両方を混乱させる**データ沼(data swamps)**になる。
- **海を沸かす**: すべてのデータを一度に直そうとせず、高価値サービス1つに結びついたパイロットから始める。

## 測定方法

**設問**
- 必要な社内データソースにどれだけ容易にアクセス・分析できるか？
- データがサイロ化され、重要な社内データを使えないことがどれほどあるか？
- 主に依存するデータの全体的な品質はどうか？
- 必要なデータポイントを検索1時間以内に確実に得られるか？

**システム指標**
- データの適時性: 必要なデータセットへのアクセス権獲得までの時間
- データインシデント: データ品質に起因するバグ・本番インシデント数
- データの鮮度: 主要データセットの「last updated」タイムスタンプ分析
