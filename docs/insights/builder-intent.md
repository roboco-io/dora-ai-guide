# AI 시대의 빌더 의도 (Builder Intent)

> 발표: 2025년 10월 · 저자: Abey Stenman, Bre Arder, Kevin M. Storer, Katharine Norwood · 원문: <https://dora.dev/insights/builder-mindset/>

## 핵심 명제

AI는 **누가 빌드할 수 있는지**를 바꿉니다. AI가 기술적 복잡성을 추상화하면서 **직무(role)가 수행 가능한 작업을 예측하지 못하게** 되었고, 역할 기반 페르소나는 빌더의 진짜 니즈를 놓칩니다. DORA는 **빌더의 의도(intent)** 를 가장 잘 드러내는 지표로 삼는 **빌더 마인드셋(Builder Mindset)** 프레임워크를 제안합니다.

## 4가지 마인드셋

| | **Founder** | **Optimizer** | **Accelerator** | **Learner** |
|---|---|---|---|---|
| **주 의도** | 수익화 — 아이디어를 빠르게 검증해 시장성 확보 | 내부 문제 해결 — 프로세스 자동화·개선 | 효율 증대 — 전문 스킬 증강, 속도 향상 | 지식 격차 해소 — 새 스킬·기술 습득 |
| **접근** | AI = 개발팀 (기술 구현을 위임) | AI = 통합자 (특정 작업의 신뢰성 검증) | AI = 파트너 (기존 스킬·도구 증강) | AI = 튜터 (단계별 기초 안내) |
| **성공 정의** | MVP까지의 속도 | ROI — 문제 해결·비용 절감 | 코드 품질 & 속도 | 역량 — 성취·새 스킬 자신감 |
| **기술 숙련** | 가변적, 종종 무관 | 기술적 소양(전업 코더는 아님) | 클래식 엔지니어링 경험 | 과제 수준의 숙련 |
| **예시 프롬프트** | "내 도시 레스토랑 딜 앱을 만들어줘" | "BigQuery 매출 DB에 연결해 지역별 대시보드를 만들어줘" | "이 컴포넌트를 class가 아니라 React hooks로 리팩터해줘" | "JS에서 API 데이터를 가져와 리스트로 표시하는 법을 설명해줘" |

이들은 고정 페르소나가 아니라 **유동적 상태**이며, 동일인도 과제에 따라 전환합니다.

## 새 설계 패러다임: 도구 조작 → 인간-AI 협업

관계가 "사람이 도구를 조작"에서 "**사람이 지능적 파트너와 협업**"으로 바뀝니다. 두 축으로 설계합니다.

- **신뢰의 스펙트럼**: 과제 대비 기술 숙련도와 신뢰는 흔히 **반비례**합니다. Founder와 (저숙련) Learner는 **위임된 높은 신뢰**로 보안 취약점 같은 심각한 리스크에 취약 → 강력한 가드레일 필수. Accelerator·Optimizer·고숙련 Learner는 **낮은 검증된 신뢰**로 투명성·통제를 최대한 요구합니다.
- **유동적·다층 추상화**: Founder는 제품 비전의 최상위 개념층, Optimizer는 통합·신뢰성의 시스템층, Accelerator는 인프라·코드의 최하위층에서 일합니다. 좋은 경험은 **층 사이를 매끄럽게 이동**하게 합니다.

## 3가지 산업적 시사점

1. **가드레일이 필수다.** 초보 Learner는 insecure한 제안을 신뢰하고, Accelerator는 검증 가능한 보안 통제를 요구합니다. **기본값이 안전해야(secure by default)** 합니다. 모든 사용자가 보안 전문가일 수는 없습니다.
2. **유동적 설계 패턴으로 추상화 갭을 메운다.** 노코드 같은 고추상 환경은 강력한 온램프지만, 문제 해결·감사·코드 확인이 필요한 시점에 벽에 부딪힙니다. 인간과 AI가 모두 **퍼스트클래스 참여자**인 다중 행위자 생태계로 설계해야 합니다. 투명성도 층에 맞게: Founder는 성공 확인만, Accelerator는 생성된 정확한 코드 가시성을 요구합니다.
3. **모두가 프로덕션을 위해 빌드한다고 가정하라.** Founder의 MVP든 Optimizer의 내부 도구든, AI 생성 산출물은 **보안·신뢰성·배포 가능·비용 투명성**이라는 프로덕션 기준을 충족해야 합니다. 기준은 "일단 작동하는 프로토타입"이 아니라 **실제 세상에 준비된 애플리케이션**입니다.

## 결론

의도는 이제 AI 에이전트가 검증·실행할 수 있는 **구조화된 스펙**이 되어가고 있습니다. GitHub의 **SpecKit** 같은 도구는 '코드가 진실의 원천'에서 '**의도가 진실의 원천**'으로의 전환을 보여줍니다.
