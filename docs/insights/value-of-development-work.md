# 생성형 AI가 개발 업무의 가치에 미치는 영향

> 발표: 2024년 12월 · 저자: Kevin M. Storer · 원문: <https://dora.dev/insights/value-of-development-work/>

## 핵심 발견: 역설

생성형 AI를 많이 쓰는 개발자는 **몰입 시간↑, 직무 만족↑, 생산성↑, 번아웃↓** 을 보고했습니다. 그러나 동시에

- **지루한 작업에 쓰는 시간은 변화 없음**
- **가치 있는 작업에 쓰는 시간은 감소**

라는 결과가 나왔습니다. AI가 "루틴 업무를 빠르게 해줘 더 나은 일을 하게 해준다"는 통념과 배치됩니다. 저자는 "가치 있는 일에 시간을 덜 쓰는데 웰빙이 좋아진다"는 역설에서 더 근본적인 질문 — **개발자는 업무의 '가치'를 어떻게 판단하는가** — 으로 이동했습니다. 2024년 9월, 약 90분씩 10명의 심층 인터뷰를 진행했습니다.

## 가치의 5가지 렌즈

| 차원 | 의미 | AI의 예상 영향 |
|---|---|---|
| **실용적(Utilitarian)** | 세상에 미치는 영향 | **긍정** — 작업 속도를 높여 영향까지의 시간 단축 |
| **평판적(Reputational)** | 수행한 일에 대한 인정 | **양가** — 실용적 가치는 높이지만, AI가 공을 가져가 소유권을 흐릴 수 있음 |
| **경제적(Economic)** | 보상 | **양가** — 생산성↑로 가치↑, 그러나 스킬 접근성↑로 희소성↓ |
| **내재적(Intrinsic)** | 배움·성취의 내재적 가치 | **중립** — 역사적으로 기술은 교육 규범을 바꿔왔음 |
| **쾌락적(Hedonistic)** | 즐거움 | **양가/중립** — 즐기는 작업을 AI가 대체하면 부정, 아니면 긍정 |

## 가치를 증폭시키는 5가지 전략

1. **SDLC 전반에서 AI 사용을 허용한다.** 실용적 가치를 중시하는 개발자는 AI를 명확한 가치 증폭기로 봤습니다. 가능한 많은 개발 작업에 허용하세요.
2. **AI와 함께하는 노동을 인정한다.** 평판적 가치를 중시하는 개발자는 AI가 자신의 공을 가져갈까 우려했습니다. 프롬프트 엔지니어, 채팅 지향 프로그래밍 같은 새 노동이 존재합니다. 리더십이 이 노동을 명시적으로 인정해야 합니다.
3. **시간이 아니라 결과에 보상한다.** 경제적 가치를 중시하는 개발자는 양가적 감정을 보였습니다. 생산성이 보상으로 이어지되, 인력·시간 감축 우려를 완화하려면 **산출물이 아닌 성과**에 보상하세요.
4. **AI를 새 스킬 학습 기회로 프레이밍한다.** 내재적 가치를 중시하는 개발자는 일부 스킬이 무의미해질까 우려했습니다. 새 기술은 "무엇을 아는가"를 바꿀 뿐 "아는 것"을 무의미하게 만들지 않음을 강조하세요.
5. **즐기는 작업에서 AI를 쓰지 않을 선택을 지원한다.** 쾌락적 가치를 중시하는 개발자에게 AI는 즐거움을 앗아갈 수 있습니다. AI 사용이 강제되는 사례는 없으므로, 원하는 개발자가 직접 하는 것을 지원하는 것이 개발의 즐거움을 보존합니다.

## 결론

개발자는 업무 가치를 **실용·평판·경제·내재·쾌락**이 얽힌 복잡한 그물로 이해합니다. AI의 역할이 계속 진화하므로 이 연구를 지속적으로 정교화해야 합니다.
