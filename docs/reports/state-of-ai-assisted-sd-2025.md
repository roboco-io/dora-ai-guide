# State of AI-assisted Software Development (2025)

> 발표: 2025년 9월 · 원문: <https://dora.dev/research/2025/dora-report/>

## 한 줄 요약

**AI의 주된 역할은 증폭기(amplifier)** 다. 즉 AI는 조직이 이미 가진 강점은 물론 약점까지도 확대한다. AI 투자의 최대 수익은 도구가 아니라 **그 아래 조직 시스템**에 대한 전략적 집중에서 나온다.

## 배경: "트릴로지"의 중심

2025년 DORA 리포트는 이름을 "Accelerate State of DevOps"에서 **State of AI-assisted Software Development**로 바꾸고, DORA를 독립된 이름으로 만들었습니다. 이 리포트는 2024 Impact 리포트를 잇는 중심축으로, 2025 AI Capabilities Model의 모체가 됩니다.

## 핵심 수치

| 지표 | 값 |
|---|---|
| 직장에서 AI를 사용하는 기술 전문가 | **90%** |
| AI가 생산성을 높였다고 답한 비율 | **80% 이상** |
| AI 생성 코드를 "거의/전혀" 신뢰하지 않는다 | **약 30%** |
| AI 도입↑ → 딜리버리 처리량 | **증가** |
| AI 도입↑ → 딜리버리 안정성 | **감소(불안정 증가)** |

## 핵심 명제

### 1. AI는 증폭기다
- 내부 플랫폼 품질이 높고, API·워크플로·테스트가 탄탄하면 AI는 강력한 협업자다.
- 도구가 파편화되고 데이터가 사일로화되며 인프라가 취약하면 AI는 **기술 부채를 더 빨리 생성**하게 돕는다.

### 2. 처리량과 안정성의 트레이드오프
AI 도입이 높을수록 **처리량과 불안정성이 함께 증가**합니다. AI가 생성 속도를 높여 배치가 커지고, 리뷰·검증 부담이 커지기 때문입니다. 이는 [AI Capabilities Model](/reports/ai-capabilities-model)의 7대 역량으로 대응합니다.

### 3. J-커브(생산성 침체)
새 기술을 도입하면 학습·프로세스 조정으로 **일시적으로 생산성이 떨어지는 구간**이 생깁니다. 이 침체를 견디고 전략적으로 실행해야 상승 곡선에 오릅니다.

### 4. 4개에서 5개로 진화한 딜리버리 지표
DORA는 전통적 "4 keys"를 **5개 지표**로 확장했습니다.

1. 변경 리드 타임(Change lead time)
2. 배포 빈도(Deployment frequency)
3. 실패 배포 복구 시간(Failed deployment recovery time)
4. 변경 실패율(Change failure percentage)
5. 배포 재작업률(Deployment rework rate) — *2025년 추가*

## 이 리포트가 남긴 것

- **측정은 결과 중심으로.** 활동량이 아니라 성과를 본다.
- **문화와 시스템이 기술보다 앞선다.** 심리적 안전, 학습 문화, 사용자 중심.
- **"AI 도입률"이 아니라 "AI 효과"를 목표로.** 도입은 필요조건이고, 효과는 시스템이 만든다.
